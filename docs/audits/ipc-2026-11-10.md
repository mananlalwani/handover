# IPC compatibility and recovery coverage

Audited November 10, 2026. This inventory covers the existing protocol-1
implementation and the local regressions added with it. It is not a stability
declaration or a record of phone testing.

## Existing evidence retained

- [`framing_tests.rs`](../../handoverd/src/ipc_server/framing_tests.rs) sends a
  fragmented request while the daemon emits an event. It protects against losing
  a request prefix when an async event wins a select branch.
- The daemon's `lag_recovery_snapshot_contains_both_state_maps` and
  `unsupported_protocol_gets_controlled_error` tests in
  [`messaging.rs`](../../handoverd/src/ipc_server/messaging.rs) check recovery
  snapshot contents and rejection of unsupported request versions. The former
  constructs snapshot data; it does not itself force a subscriber to lag.
- [`snapshot_tests.rs`](../../crates/handover-ipc/src/snapshot_tests.rs) checks
  aggregate byte and chunk limits, exact reconstruction, and rejection without
  publishing an oversized partial snapshot.
- [`hardening_tests.rs`](../../crates/handover-ipc/src/hardening_tests.rs) covers
  bounded list assembly, ordered reconstruction, interrupted list kinds, and
  diagnostics that omit rejected private content.
- [`ipc-limits.test.mjs`](../../quickshell/tests/ipc-limits.test.mjs) covers atomic
  snapshots, interruption, disconnect cleanup, UTF-8 byte accounting, and limits.
  [`share.test.mjs`](../../quickshell/tests/share.test.mjs) checks transfer evidence,
  early-event ordering, unknown outcomes, and no replay after disconnect.
- The desktop bridge's
  [`recovery.rs`](../../handover-desktop/src/integration/recovery.rs) checks silent
  snapshot baselines after daemon reconnect and notification-service replacement.
  These use a private D-Bus session, not the user's notification service.

## Gaps closed

Quickshell bounded notification and media lists, but contact-list assembly had
no aggregate byte or chunk budget. Conversation and outgoing-operation chunks
published incremental state before the final chunk. Focused tests reproduced
the missing contact limits and early conversation publication before the fix.

All five complete-list variants now use one assembly budget and reject
interleaved records. Contacts and outgoing operations replace their collection
only on completion; account-scoped conversation responses merge only after the
complete response arrives. Disconnect discards the unfinished assembly. No wire
shape, capability, or protocol number changed.

A new daemon-boundary test forces a real subscriber to overflow the broadcast
channel while another client can still query current state. It exposed stale
queued events replaying after the replacement snapshot. Recovery now subscribes
at the channel's current tail before taking the snapshot, discarding superseded
events while retaining new events arriving during snapshot construction or
delivery. The regression observed a current 99% battery snapshot followed by a
stale 36% update before the fix; after the fix, the next update is the new 100%
state. Transient events missed during lag remain intentionally unreplayed.

Rust-client boundary tests now cover:

- Fragmentation inside multibyte UTF-8 and multiple consecutive snapshot records.
- EOF between chunks and inside a record, for both initial and recovery snapshots.
- Recovery snapshots interrupted by another response or a different chunk kind.
- Unsupported server envelope versions before returning state to the caller.
- A notification mutation whose request reaches the daemon but whose reply is
  lost. The client returns a connection error and sends no second request.

The last test proves no automatic resend at the Rust client boundary. It does
not establish whether a real phone acted. `Client::hello` remains a query;
callers check its supported-version list. The CLI already performs that check.

## Verification and remaining limits

Run the Rust workspace suite, QML lint, JavaScript tests, the send-window fixture,
and launcher tests using [Contributing](../../CONTRIBUTING.md).

Fixture coverage does not prove bounded resident memory under every workload or
compatibility with every historical release. No load benchmark, physical-phone
reconnect test, or public IPC stability commitment is claimed here.
