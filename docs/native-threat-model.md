# Native backend threat model

The first native link carries device presence and battery state on a local network. The LAN is untrusted: another host can observe, drop, replay, modify, or impersonate discovery advertisements and connections. A lost phone or compromised desktop account can expose that endpoint's stored identity. An attacker can also flood discovery or open many sockets.

The Android user and Linux user must explicitly approve the same peer identity during pairing. Pairing must bind that approval to a persistent public key, and later connections must authenticate the stored key before any device state enters Handover. Discovery is only a hint for where to connect. It never grants trust. Unpairing deletes local trust and closes the current connection; a stale peer cannot silently restore it. Encryption and authentication protect messages in transit. Bounded framing, timeouts, and limited concurrent sessions contain malformed or stalled peers.

The eight-digit code is a verification value, never a secret or key material: each ceremony commits to fresh random nonces in the hellos, reveals them in `pair_open`, and derives the code from both certificate fingerprints with each nonce bound to its fingerprint owner. Committing before revealing denies a middlebox the offline grinding a static fingerprint-only code would allow; it gets at most one guess per user-visible ceremony. The server verifies that the phone's `pair_confirm` repeats the displayed code and drops the session on any mismatch or on an opening that does not match the commitment, so a ceremony permits no silent retries. No attempt counter is kept on the local IPC approval path because any process with same-user socket access can already read the pending code; the wire-side abort-on-mismatch is the effective limit.

The protocol does not defend against an endpoint whose OS or app data is compromised, a user approving the wrong comparison code, or metadata exposed by local discovery. Per-source admission limits, a rolling connection-attempt bound, bounded tracked-source state, and pre-auth socket timeouts reduce—but do not eliminate—LAN denial of service. Battery is remote-reported data, so Handover validates its range but cannot prove its truth. Revocation is local on each side; the other side may retain its old trust record until it also unpairs. DNS-SD has deterministic record tests plus an opt-in ignored live advertise/browse test; normal CI does not require multicast support.

Security design must use a maintained, interoperable cryptographic transport. No homegrown key exchange, cipher construction, or encrypted record format is acceptable. The final transport and pairing flow are recorded in `DESIGN.md` after API research.
